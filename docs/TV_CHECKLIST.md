# テレビでの確認

公開後、テレビのブラウザから実際のGitHub Pagesページを開いて実施します。判定はこの機種・この接続先・この動画の組み合わせに限ります。

## 1. 基本再生

「テレビの基本再生テスト」を押します。約10秒の模様が動き、小さな確認音が聞こえることを確認します。テレビの音量とミュート状態も確認します。これはYouTubeではなく同梱動画です。

ここで失敗した場合、外部Pipedの調査より先にテレビの再生形式・ブラウザ・操作を確認します。

## 2. 通常のYouTube動画

公開されている通常動画のURLを入力します。初回は年齢制限・ログイン・有料視聴が不要な動画を選びます。接続先を選び、送信確認にチェックして「動画情報を取得」を押します。

接続先がHTTPエラーや通信エラーを返す場合はレポートを残します。別の接続先を試すときは手動で変更し、再度送信確認にチェックします。

## 3. 再生と継続

「再生 / 一時停止」を押します。映像と音声が出たら「映像と音声を確認できた」を押します。このボタンを押す前に、実際に絵と音が正常なことを確かめます。

1本につき3分程度の継続視聴、10秒戻る/進む、全画面、一時停止と再開を試します。別の通常動画でも確認します。成功時も診断を保存します。

## 4. 成立の判定

以下を別々に記録します。

- 基本再生テストが成功したか。
- 実APIからJSONを受け取れたか。
- 実動画の映像と音声が出たか。
- 継続再生とシークに問題がないか。

1つ目や2つ目だけでは、YouTube視聴成功とはしません。ライブ配信だけの成功も、通常動画の成功とは分けます。

診断に `NETWORK` と出ても、CORSだけが原因とは判断しません。PCのブラウザの開発者ツールでHTTP、証明書、DNS、CORSを切り分ける必要があります。このPCは調査のためだけに用い、視聴の中継には使いません。
